# 004. Design a Web Crawler (Scraper / Search Engine Indexer)

## 1. Problem Statement & Requirements
### Functional Requirements:
- Discover and download web pages given a set of seed URLs.
- Extract links from pages and add them to the crawl queue.
- Store downloaded web pages in storage.

### Non-Functional Requirements:
- Scalability to crawl billions of pages.
- Politeness (do not overwhelm target websites).
- Extensibility and fault tolerance.

## 2. High-Level Architecture
1. **URL Frontier**: Manages queues of URLs to crawl, respecting politeness delays.
2. **DNS Resolver**: Resolves domains to IPs.
3. **Fetcher / Downloader**: Fetches HTML pages over HTTP.
4. **HTML Parser**: Extracts links and content.
5. **Duplicate Detector**: Uses Bloom Filters and checksums to avoid re-crawling.
6. **Storage**: Saves raw HTML to distributed storage (HDFS / S3).

## 3. Deep Dive
- **Politeness**: FIFO queues per domain with delay timers.
- **Priority Queues**: Prioritize important pages (pagerank-based).
