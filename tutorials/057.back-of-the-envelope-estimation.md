# 057. Back-of-the-Envelope Estimation

## Overview
Quickly estimating scale, storage, bandwidth, and compute requirements is a critical skill for system design interviews, allowing you to validate design feasibility and identify bottlenecks.

## Fundamental Reference Numbers (The "Must-Knows")
Memorize baseline latency numbers and the "Power of Two" table to perform rapid, mental calculations.

| Metric | Latency |
| :--- | :--- |
| L1 cache reference | 0.5 ns |
| RAM reference | 100 ns |
| SSD random read | 16,000 ns |
| Cross-datacenter RTT | ~150 ms |

### Power of Two Table
- $2^{10} = 1 \text{ KB}$
- $2^{20} = 1 \text{ MB}$
- $2^{30} = 1 \text{ GB}$
- $2^{40} = 1 \text{ TB}$

## Core Estimation Framework
Use a structured, formulaic approach during interviews.

### 1. Traffic (QPS) Calculation
Calculate Average QPS using Daily Active Users (DAU) and requests per user per day.
$$\text{QPS} = \frac{\text{DAU} \times \text{Requests per User per Day}}{86,400 \text{ seconds}}$$
*Note: Multiply average QPS by 2 to 3 to estimate **Peak QPS**.*

### 2. Storage Sizing
$$\text{Storage} = \text{Daily Active Users} \times \text{Data per User per Day} \times \text{Retention Period}$$
*Include factors for replication, backups, and projected growth (e.g., 3-5 years).*

### 3. Bandwidth Estimation
$$\text{Bandwidth} = \text{QPS} \times \text{Average Payload Size}$$

## Common Practice Case Studies
- **URL Shortener**: Estimating storage for billions of URL mappings over 5 years.
- **Chat Application**: Calculating message throughput and peak traffic during high-load events.
- **News Feed**: Projecting storage for billions of posts and image metadata.
