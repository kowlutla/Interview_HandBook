# 015. Rate Limiting and Throttling

## Overview
Rate limiting protects services from abuse, overuse, and DDoS attacks by restricting request rates.

## Common Algorithms
- **Token Bucket**: Tokens added at fixed rate; each request consumes a token. Allows burst traffic.
- **Leaky Bucket**: Requests processed at fixed rate; excess requests queue or drop. Smooths traffic.
- **Fixed Window**: Counts requests per time window. Simpler but allows burst at window boundaries.
- **Sliding Window**: More accurate, tracks requests in a rolling time window.

## Implementation
- **Client-side**: Prevents wasted requests but can be bypassed.
- **Server-side**: More secure, typically at API Gateway or load balancer.
- **Distributed**: Use Redis or similar for shared state across multiple nodes.
