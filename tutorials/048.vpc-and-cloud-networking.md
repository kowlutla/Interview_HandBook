# 048. VPC and Cloud Networking

## Overview
A Virtual Private Cloud (VPC) is a logically isolated virtual network that you define in your cloud provider's network, where you can launch resources. This tutorial covers network architecture, connectivity, and security boundaries.

## 1. Executive Summary & Core Definition
A VPC provides a private sandbox within a public cloud. It enables complete control over your virtual networking environment, including selection of your own IP address range, creation of subnets, and configuration of route tables and network gateways.

## 2. Deep-Dive Architecture & Core Principles
### Core Components
- **VPC (Virtual Private Cloud)**: The container for your networking infrastructure.
- **Subnets**: Segmentation of the VPC IP range.
  - **Public Subnet**: Connected to an Internet Gateway for outbound/inbound traffic.
  - **Private Subnet**: Isolated; requires NAT Gateway for outbound traffic.
- **Route Tables**: Rules that determine where network traffic is directed.
- **Network ACLs & Security Groups**: The primary firewalls.
  - **Security Groups**: Stateful, instance-level firewalls.
  - **NACLs**: Stateless, subnet-level firewalls.

## 4. Real-World Industry Use Cases
- **Multi-Region VPCs**: Connecting VPCs in different AWS regions for disaster recovery.
- **Hybrid Cloud**: Connecting on-premises data centers to cloud VPCs using AWS Direct Connect or VPN.

## 5. Common Pitfalls & Anti-Patterns
- **Overlapping CIDR Blocks**: Causes routing conflicts when peering VPCs.
- **Overly Permissive Security Groups**: Allowing `0.0.0.0/0` on sensitive ports (e.g., 22, 3306).
- **Hardcoding Network Configs**: Always use IaC for repeatable networking.
