## 1. Executive Summary & Philosophy

As web applications scale globally, serving static and dynamic assets directly from a centralized origin server introduces massive latency and bandwidth costs governed by the speed of light and network hop counts. 

A **Content Delivery Network (CDN)** is a geographically distributed network of proxy servers and data centers (Points of Presence, or PoPs) designed to cache content at the "edge" of the internet, as close to end users as possible. CDNs reduce origin server load, accelerate Time-to-First-Byte (TTFB), and absorb volumetric Distributed Denial of Service (DDoS) attacks.

---

## 2. Core Architecture & Operation

```
[ Global Users ] ---> [ Edge PoP (Anycast Routing) ]
                             | (Cache Hit: Returns instantly)
                             | (Cache Miss: Fetches from Origin)
                             v
                     [ Origin Infrastructure ]
```

### 2.1 Points of Presence (PoPs) and Edge Servers
A CDN consists of hundreds of PoPs worldwide. Each PoP contains high-performance caching servers equipped with SSD/NVMe storage and high-throughput network interfaces.

### 2.2 Routing via Anycast
When a user requests an asset, **Anycast DNS** routes the client's request to the topologically closest PoP, minimizing physical network hops.

## 3. Pull vs. Push CDN Models

1.  **Pull CDN (On-Demand Caching)**:
    *   **Mechanism**: The CDN edge server acts as a reverse proxy. When a user requests an asset that is not currently cached (a cache miss), the edge server fetches the file from the origin server, caches a copy locally, and returns it to the user.
    *   **Pros**: Simple to set up; only requested files consume storage.
    *   **Cons**: First user experience a latency penalty (cache miss).
2.  **Push CDN (Pre-Population)**:
    *   **Mechanism**: The origin server explicitly uploads/pushes all static assets directly to the CDN storage cluster upon deployment.
    *   **Pros**: Guaranteed cache hits; no cold start latency for users.
    *   **Cons**: Wastes storage on unpopular assets; requires complex deployment pipelines.

## 4. Cache Management and Invalidation

Managing cache lifecycle is critical to prevent serving stale data while maximizing cache hit ratios (CHR).

### 4.1 Cache Control Headers
*   `Cache-Control: public, max-age=31536000, immutable`: Tells the CDN and browser to cache the asset for 1 year without revalidation (ideal for hashed static assets like `main.a98f12.js`).
*   `Cache-Control: s-maxage=3600`: Specifies CDN-specific caching duration separate from browser caching (`max-age`).
*   `stale-while-revalidate`: Serves stale content instantly while asynchronously fetching fresh content from the origin in the background.

### 4.2 Cache Invalidation Strategies
1.  **TTL Expiry**: Relying on expiration timers (`max-age`). Simple but prone to serving stale updates until TTL expires.
2.  **Purging / Invalidation API**: Explicitly issuing an API call to the CDN vendor to invalidate specific URLs or cache tags immediately upon deployment.
3.  **Versioning / Cache Busting**: Appending unique cryptographic hashes or version numbers to file names (`script.v2.js`), rendering old cache entries obsolete.

## 5. Modern Edge Computing & Dynamic Acceleration

Modern CDNs (e.g., Cloudflare Workers, AWS CloudFront Functions, Fastly Compute@Edge) have evolved from static asset caches into **serverless edge compute platforms**. 

*   **Edge Routing & A/B Testing**: Executing lightweight JavaScript/Wasm at the edge to inspect cookies, rewrite headers, or route traffic before hitting origin servers.
*   **Edge Authentication**: Verifying JWT tokens or OAuth signatures at the edge, rejecting unauthorized requests before they consume origin compute resources.

---

## 6. Security and DDoS Mitigation

CDNs serve as the primary defensive perimeter for modern web infrastructure:
*   **Layer 3/4 & Layer 7 DDoS Absorption**: Massive distributed edge capacity absorbs volumetric SYN floods, UDP floods, and HTTP Layer 7 application attacks.
*   **Web Application Firewall (WAF)**: Inspecting incoming payloads for SQL injection, Cross-Site Scripting (XSS), and zero-day exploit patterns at the edge.
*   **SSL/TLS Termination**: Handling TLS handshakes at the edge, reducing cryptographic overhead on origin servers.
