# 053. LSM-Trees vs. B-Trees

## Overview
Understanding storage engine indexing structures and their write vs. read performance trade-offs.

## B-Tree
- Classic balanced tree structure used in traditional relational databases (MySQL/InnoDB).
- **Reads**: Fast O(log n).
- **Writes**: Slower, involves in-place disk page updates and random I/O.

## LSM-Tree (Log-Structured Merge-Tree)
- Optimized for high write throughput (Cassandra, RocksDB, LevelDB).
- Writes go to memory (MemTable) and append-only disk logs (CommitLog/SSTables).
- **Writes**: Extremely fast (sequential I/O).
- **Reads**: May require checking multiple SSTables and compaction.
