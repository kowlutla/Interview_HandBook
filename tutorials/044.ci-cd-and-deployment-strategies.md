# 044. CI/CD and Deployment Strategies

## Overview
Automated testing, continuous integration (CI), and continuous deployment (CD) are fundamental to modern software engineering, enabling teams to deliver features rapidly with high reliability and zero downtime.

## 1. CI/CD Pipeline Fundamentals
A robust pipeline automates the journey from code commit to production.
*   **Source Control (SCM)**: The trigger for the pipeline (e.g., GitHub, GitLab).
*   **Build Phase**: Compiling code, resolving dependencies, and packaging artifacts (Docker images, binaries).
*   **Testing Phase**:
    *   **Unit Tests**: Fast, isolated tests for individual components.
    *   **Integration Tests**: Validating interactions between modules, databases, and APIs.
    *   **Security Scanning**: SAST (Static Application Security Testing) and DAST (Dynamic Application Security Testing).
*   **Artifact Registry**: Storing immutable versions of the application (e.g., Docker Hub, ECR, Artifactory).

## 2. Advanced Deployment Strategies
The goal is to eliminate risk during releases.
*   **Blue-Green Deployment**:
    *   **Mechanism**: Two identical production environments. Traffic is switched at the load balancer level from Blue (current) to Green (new).
    *   **Benefit**: Instant rollback by switching traffic back.
*   **Canary Deployment**:
    *   **Mechanism**: Traffic is shifted incrementally to a small subset of servers running the new version. If metrics (error rate, latency) are healthy, traffic is increased.
    *   **Benefit**: Limits impact if the new version has bugs.
*   **Rolling Update**:
    *   **Mechanism**: Incrementally updating instances in the server pool until all are on the new version.
    *   **Benefit**: No downtime, minimal resource overhead, but harder to roll back instantly.

## 3. Infrastructure as Code (IaC)
CI/CD is inseparable from IaC for environment reproducibility.
*   **Tools**: Terraform, Pulumi, AWS CloudFormation.
*   **Best Practice**: Treat infrastructure changes just like application code (version control, PRs, automated tests).

## 4. Observability Integration
CI/CD shouldn't stop at deployment.
*   **Automated Rollback**: If monitoring systems (e.g., Prometheus, Datadog) detect an anomaly after deployment, trigger an automated rollback.
*   **Deployment Markers**: Adding markers in observability tools to correlate performance changes with specific releases.
