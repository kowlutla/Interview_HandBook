## 2. The OSI 7-Layer Model

The Open Systems Interconnection (OSI) model standardizes network communication into seven distinct abstraction layers. Each layer encapsulates data from the layer above and adds its own header information.

```
+-----------------------------------------------------------------+
|                        OSI 7-LAYER MODEL                        |
|                                                                 |
|  Layer 7: Application    (HTTP, gRPC, DNS, TLS, WebSocket)      |
|  Layer 6: Presentation   (Encryption, Serialization, Compression)|
|  Layer 5: Session        (Session establishment, Authentication)|
|  Layer 4: Transport      (TCP, UDP, SCTP - End-to-end delivery) |
|  Layer 3: Network        (IP, ICMP, Routing, Addressing)        |
|  Layer 2: Data Link      (Ethernet, MAC addressing, Framing)    |
|  Layer 1: Physical       (Cables, Optical fiber, Radio waves)   |
+-----------------------------------------------------------------+
```

### Key Layers for System Architects:
*   **Layer 3 (Network)**: Operates via IP (Internet Protocol). Handles packet routing across independent subnets and routers.
*   **Layer 4 (Transport)**: Operates via TCP and UDP. Manages end-to-end communication reliability, packet sequencing, and port multiplexing.
*   **Layer 7 (Application)**: Protocols consumed directly by software applications (HTTP/1.1, HTTP/2, HTTP/3, gRPC).

## 3. Transmission Control Protocol (TCP)

TCP is a **connection-oriented, reliable, byte-stream protocol** designed to guarantee error-free, ordered delivery of data across unreliable networks.

### 3.1 The 3-Way Handshake
Before data transmission begins, TCP establishes a synchronized connection using a 3-way handshake:
1.  **SYN**: Client sends a packet with the `SYN` (synchronize) flag and an initial sequence number ($ISN_c$).
2.  **SYN-ACK**: Server responds with `SYN-ACK`, acknowledging the client's sequence number ($ISN_c + 1$) and providing its own initial sequence number ($ISN_s$).
3.  **ACK**: Client sends an `ACK` acknowledging the server's sequence number ($ISN_s + 1$). Connection is now established.

```
Client                                      Server
  | ----- [SYN] (seq=x) --------------------> |
  | <---- [SYN-ACK] (seq=y, ack=x+1) -------- |
  | ----- [ACK] (ack=y+1) ------------------> |
  [Established]                               [Established]
```

### 3.2 Flow Control (Sliding Window)
To prevent a fast sender from overwhelming a slow receiver's memory buffer, TCP uses **Flow Control**. The receiver advertises its available buffer space (`Receive Window` or `rwnd`) inside every acknowledgment packet. The sender restricts its unacknowledged bytes to remain within the receiver's `rwnd`.

### 3.3 Congestion Control
While flow control protects the *receiver*, **Congestion Control** protects the *network* from router bottlenecks. TCP employs algorithms (such as Cubic, Reno, BBR) governed by four core mechanisms:
1.  **Slow Start**: Exponentially increasing the congestion window (`cwnd`) upon connection startup until packet loss occurs.
2.  **Congestion Avoidance**: Incrementing `cwnd` linearly once the slow-start threshold is reached.
3.  **Fast Retransmit & Fast Recovery**: Resending lost segments immediately upon receiving duplicate ACKs without waiting for retransmission timers to expire.

## 4. User Datagram Protocol (UDP)

UDP is a **connectionless, unreliable, message-oriented datagram protocol**. It provides no handshakes, no connection state, no flow control, no congestion control, and no delivery guarantees. Packets may arrive out of order, be duplicated, or be dropped entirely.

### 4.1 When to Use UDP
*   **Real-Time Streaming**: VoIP, video conferencing (Zoom, WebRTC) where dropping a late frame is preferable to pausing the entire stream for retransmission.
*   **High-Frequency Gaming**: Multiplayer state synchronization where stale packets are useless.
*   **DNS & DHCP**: Lightweight queries requiring minimal overhead.

## 5. Modern Transport: HTTP/3 and QUIC

Traditional HTTP/2 runs over TCP, which suffers from **Head-of-Line (HoL) Blocking at the transport layer**: if a single TCP packet is dropped, all streams multiplexed over that TCP connection stall until the lost packet is retransmitted.

*   **QUIC**: Developed by Google and standardized by the IETF, QUIC runs on top of **UDP** and introduces application-layer multiplexing.
*   **Key Advantages**:
    *   **Zero-RTT Connection Establishment**: Combines transport handshake and TLS 1.3 cryptographic handshake.
    *   **Stream-Level Multiplexing**: Packet loss on stream A does not block data transmission on stream B.
    *   **Connection Migration**: Seamlessly transitions between Wi-Fi and cellular networks using a connection ID rather than IP addresses.

## 6. Comparative Analysis: TCP vs. UDP vs. QUIC

| Dimension | TCP | UDP | QUIC (HTTP/3) |
| :--- | :--- | :--- | :--- |
| **Reliability** | Guaranteed (Retransmissions) | None (Best effort) | Guaranteed (Stream-level) |
| **Ordering** | Strict byte-stream ordering | None | Stream-level ordering |
| **Handshake Latency** | 1 to 3 RTT (TCP + TLS) | 0 RTT | 0 to 1 RTT (Combined TLS 1.3) |
| **Head-of-Line Blocking** | Transport-layer blocking | None | None |
| **Primary Use Cases** | Web (HTTP/1.1, HTTP/2), Databases, SSH | DNS, NTP, Video Streaming, Gaming | Modern Web (HTTP/3), Mobile Apps |
