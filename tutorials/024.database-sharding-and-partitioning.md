# 019. Database Sharding and Partitioning

## Overview
Sharding and partitioning distribute data across multiple databases to improve scalability.

## Horizontal Partitioning (Sharding)
- Distributes rows across different databases/nodes.
- Each shard contains a subset of data (e.g., by user ID range or hash).

## Vertical Partitioning
- Distributes columns across different tables/databases.
- Frequently accessed columns on faster storage.

## Sharding Strategies
- **Range-based**: Shard by ID ranges (e.g., 1-1000, 1001-2000). Simple but can cause hot spots.
- **Hash-based**: Hash key mod number of shards. Better distribution but complex to reshard.
- **Directory-based**: Lookup service maps keys to shards. Flexible but adds latency.

## Challenges
- Cross-shard queries (joins, transactions).
- Rebalancing when adding shards.
- Data migration.
