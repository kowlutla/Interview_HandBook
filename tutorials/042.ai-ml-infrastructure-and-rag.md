# 042. AI/ML Infrastructure and RAG

## Overview
Designing robust systems to integrate Large Language Models (LLMs) and machine learning workflows. This covers the architecture required to go from raw data to model serving, including retrieval, fine-tuning, and evaluation.

## 1. The ML Pipeline Architecture
A mature ML pipeline is a continuous loop rather than a linear process.
*   **Data Ingestion & Preprocessing**: Collecting raw data from diverse sources, cleaning, deduplication, and transformation.
*   **Feature Store**: A centralized repository to manage, store, and serve features for both training and inference, ensuring consistency (e.g., Feast, Tecton).
*   **Model Training**: Orchestrating large-scale training jobs, managing experiments, and hyperparameter tuning (e.g., Kubeflow, SageMaker, Ray).
*   **Model Registry & Versioning**: Managing model artifacts, metadata, and lineages (e.g., MLflow, Weights & Biases).
*   **Model Serving (Inference)**: Serving predictions with low latency. Strategies include batch inference, real-time API serving, or streaming inference.

## 2. Retrieval-Augmented Generation (RAG)
RAG addresses the limitations of LLMs (hallucinations, lack of domain knowledge, knowledge cut-offs) by grounding them in external, private, or real-time data.

### The RAG Pipeline
1.  **Ingestion & Indexing (Offline)**:
    *   **Document Loading & Splitting**: Parsing unstructured documents (PDFs, Markdown, Web) into manageable chunks.
    *   **Embedding**: Using an embedding model (e.g., OpenAI `text-embedding-3`, HuggingFace models) to convert chunks into dense vector representations.
    *   **Vector Database**: Storing these embeddings for fast semantic similarity search (e.g., Pinecone, Milvus, Qdrant, Weaviate, pgvector).
2.  **Retrieval & Generation (Online)**:
    *   **Query Embedding**: Converting the user's prompt into a vector.
    *   **Similarity Search**: Finding top-k relevant chunks based on vector similarity (Cosine, Euclidean, or Dot Product).
    *   **Augmentation**: Creating a prompt that combines the original user query and the retrieved context.
    *   **Generation**: LLM generates the final answer based on the augmented prompt.

## 3. Evaluation & Guardrails
*   **Evaluation (RAGAS / TruLens)**: Metrics like faithfulness, answer relevance, and context precision.
*   **Guardrails**: Mechanisms to prevent PII leakage, prompt injection, or biased/harmful outputs (e.g., NeMo Guardrails, Guardrails AI).

## 4. Architectural Trade-offs
*   **Serverless vs. Provisioned Inference**: Cost vs. cold start latency.
*   **Fine-tuning vs. RAG**: RAG is better for knowledge updates and citation; fine-tuning is better for style, tone, and domain-specific vocabulary.
