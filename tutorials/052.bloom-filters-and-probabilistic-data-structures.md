# 052. Bloom Filters & Probabilistic Data Structures

## Overview
In distributed systems and large-scale data engineering, exact set membership and counting operations at scale consume prohibitive amounts of memory. Probabilistic data structures trade absolute certainty for exponential space savings, allowing engineers to handle billions of items with tiny memory footprints. This tutorial covers Bloom filters, Count-Min Sketches, HyperLogLog, and MinHash/SimHash, along with their real-world system design applications.

---

## 1. Bloom Filters

### Core Mechanics
A Bloom filter is a space-efficient probabilistic data structure used to test whether an element is a member of a set.
- **Data Structure**: A bit array of length $m$, all initialized to 0, and $k$ independent hash functions, each mapping an input to one of the $m$ positions.
- **Insertion**: When an item is added, pass it through the $k$ hash functions to get $k$ indices, and set the bits at those indices to 1.
- **Membership Query**: To test if an item is in the set, pass it through the same $k$ hash functions. 
  - If **any** of the bits at those indices is 0, the item is **definitely not** in the set (zero false negatives).
  - If **all** bits are 1, the item is **probably** in the set (false positives are possible).

### Mathematical Sizing Formulas
Given expected number of items $n$ and desired false positive probability $p$:
- **Optimal bit array size ($m$)**: 
  $$m = -\frac{n \ln p}{(\ln 2)^2}$$
- **Optimal number of hash functions ($k$)**: 
  $$k = \frac{m}{n} \ln 2$$

### System Design Use Cases
1. **Cache Penetration Prevention**: Before querying a database for a non-existent primary key requested by users (malicious or accidental), check a Bloom filter. If the filter returns false, bypass the cache and database entirely, preventing cache stampedes.
2. **Database Storage Engine Optimization**: In LSM-tree storage engines (like Cassandra or RocksDB), each Sorted String Table (SSTable) on disk is paired with a Bloom filter. When reading a key, the engine checks the filter to instantly skip SSTables that do not contain the key, eliminating expensive disk seeks.
3. **Web Crawling URL Deduplication**: Tracking billions of visited URLs in memory requires gigabytes using hashtables. A Bloom filter reduces memory consumption to a few megabytes while maintaining acceptable false positive rates (e.g., crawling an already visited URL once in a million).

## 2. Count-Min Sketch

### Core Mechanics
The Count-Min Sketch is a frequency-estimation streaming data structure used to find "heavy hitters" (e.g., top-K trending hashtags, IP addresses, or search terms) in data streams where exact frequency counting is memory-prohibitive.
- **Data Structure**: A 2D array of counters with depth $d$ (number of hash functions) and width $w$ (number of buckets per row).
- **Update**: When an event arrives, pass it through $d$ hash functions to obtain $d$ indices, and increment the counter at each respective row and column by the event's weight.
- **Query**: To estimate the frequency of an item, take the minimum value across all $d$ hashed counter positions: $\min(C[1, h_1(x)], C[2, h_2(x)], \dots, C[d, h_d(x)])$.
- **Error Bounds**: Overestimates frequencies due to hash collisions, but never underestimates. Error bounds and probability guarantees depend on choices of $d$ and $w$.

## 3. HyperLogLog (HLL)

### Core Mechanics
HyperLogLog is an algorithm for approximating the cardinality (number of distinct elements) of massive datasets with astonishing memory efficiency.
- **Memory Footprint**: Can estimate millions or billions of unique items (e.g., unique daily active users or website views) in just **12 to 15 kilobytes** of memory with standard errors under 1-2%.
- **Principle**: Based on the observation that the cardinality of a multiset can be estimated by observing the maximum number of leading zeros in the binary representations of hashed incoming items. Using stochastic averaging and harmonic means, HLL smooths out variance.

---

## 4. MinHash & SimHash (Similarity Detection)

- **MinHash**: Estimates the Jaccard similarity between two sets. Widely used in recommendation systems, plagiarism detection, and clustering similar documents.
- **SimHash**: Generates locality-sensitive hashes for documents or web pages such that similar documents have identical or very close Hamming distances. Used by web search engines for near-duplicate detection and web spam filtering.
