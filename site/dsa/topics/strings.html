START WITH THE RIGHT QUESTION

How should I approach a string problem?

Do not start by writing loops. First identify what the problem asks you to preserve: character frequency, relative order, a one-to-one relationship, or a pattern between neighbouring positions.

  1. Understand the contractInput size, allowed characters, case sensitivity and expected output.
  2. Find the relationshipAre we counting, matching, mapping, comparing or constructing?
  3. Choose what to rememberA frequency array, map, last-seen index, two pointers or a stack.
  4. State the invariantExplain what must remain true after every iteration.
  5. Test the boundary casesRepeated characters, collisions, empty input and the smallest valid input.

Isomorphic Strings

Determine whether two strings have the same character structure, even when their actual characters are different.

INPUTs = "paper"t = "title"
OUTPUTtrue
UnderstandObservationSolutionWhy it worksPractice

1. Understand the problem

We are given two strings of equal length. We need to decide whether we can replace every character in the first string with a character in the second string so that the strings become identical.

The replacement must be consistent. If p becomes t once, every later p must also become t. The mapping must also be one-to-one: two different characters from the first string cannot share the same replacement character.

✓ Isomorphic"egg" → "add"

e → a and g → d. The repeated-character structure is preserved.

✕ Not isomorphic"foo" → "bar"

The two o characters would need to map to both a and r.

✕ Not isomorphic"ab" → "aa"

Both a and b would map to the same target a.

✓ Isomorphic"paper" → "title"

p → t, a → i, e → l, r → e.

What matters: The letters themselves do not matter. The positions at which characters repeat must have the same structure in both strings.

2. Build the intuition

Take str1 = "paper" and str2 = "title". Compare the characters at each position and record a mapping in both directions.

When the first p is paired with t, the method records both directions: p → t and t → p. When the pair appears again at index 2, both stored mappings agree, so processing can continue.

With "foo" and "bar", the first pair records f → b and b → f. At the next position, o has no mapping but a is already mapped from b. The new pair conflicts with the reverse mapping and is rejected.

💡
The key observation

A one-way mapping is not enough. Store the mapping in both directions so that one source character cannot map to multiple targets and multiple source characters cannot map to the same target.

3. How your implementation stores the mapping

4. Java implementation from your DSA repository

This is the method in IsomorphicStrings.java. It first checks equal lengths, then uses two 256-element arrays to store the forward and reverse character mappings. An entry of -1 means no mapping has been assigned yet.

public static boolean areIsomorphic(String str1, String str2) {
    // Isomorphic strings must have the same length.
    if (str1.length() != str2.length()) {
        return false;
    }

    // count1[c1] stores c1 -> c2; count2[c2] stores the reverse c2 -> c1.
    int[] count1 = new int[256];
    int[] count2 = new int[256];

    // -1 means that this character does not have a mapping yet.
    Arrays.fill(count1, -1);
    Arrays.fill(count2, -1);

    // Process the two strings at the same index.
    for (int i = 0; i < str1.length(); i++) {
        char c1 = str1.charAt(i); // Current character from the first string.
        char c2 = str2.charAt(i); // Character it must map to in the second string.

        // If neither character is mapped, create the mapping in both directions.
        if (count1[c1] == -1 && count2[c2] == -1) {
            count1[c1] = c2; // Record the forward mapping: c1 -> c2.
            count2[c2] = c1; // Record the reverse mapping: c2 -> c1.
        } else if (count1[c1] != c2 || count2[c2] != c1) {
            // Either direction conflicts with an earlier mapping.
            return false;
        }
    }

    // Every character pair respected the same one-to-one mapping.
    return true;
}

The source file imports java.util.Arrays. Because the arrays have 256 entries, every input character must have a numeric char value from 0 to 255; larger values can cause ArrayIndexOutOfBoundsException. The method also assumes non-null inputs and does not validate them.

6. Why is this correct?

Invariant: After processing each pair of characters, every mapping recorded in count1 and count2 agrees with all pairs seen so far.

  • Neither character has a mapping: The pair is new in both directions, so recording c1 → c2 and c2 → c1 preserves a one-to-one relationship.
  • A mapping already exists: Both directions must match the current pair. If either direction differs, the mapping is inconsistent and the method returns false.
  • The scan completes: Every position respected the same forward and reverse mappings. Therefore the character substitution is consistent and one-to-one.

The reverse array is essential: it prevents two different characters in the first string from being mapped to the same character in the second string.

7. Complexity analysis

TIMEO(n)

Two fixed arrays of 256 elements are initialized, then the method scans the n character pairs once.

AUXILIARY SPACEO(1)

The two arrays always contain 256 integers each, regardless of input length.

More precisely, initialization costs O(256) and scanning costs O(n), so total time is O(256 + n), which simplifies to O(n) because 256 is constant.

8. Common mistakes and edge cases

  • Using only a forward map. It accepts "ab" → "aa", even though two source characters collide on one target.
  • Comparing character frequencies only. Frequency counts ignore order. The positions of repeated characters are what matter.
  • Assuming every Java character fits in 256 slots. That is safe only under a stated byte/ASCII constraint, not for all Java char values.
  • Using only one mapping direction. The reverse array is necessary to prevent two source characters from mapping to the same target character.
  • Ignoring input assumptions. This implementation uses arrays of length 256, so input characters must fit in the range 0–255. The method also expects non-null strings.

MEDIUM

Minimum Number Following an I/D Pattern

Construct the smallest number whose adjacent digits follow the given increasing (I) and decreasing (D) pattern.

INPUTpattern = "IDID"
OUTPUT13254
UnderstandObservationSolutionWhy it worksPractice

1. Understand the problem

We are given a pattern made only of I and D. We must return the smallest number using distinct digits from 1 to 9, with one more digit than the pattern length.

  • I means the next digit must be greater than the current digit.
  • D means the next digit must be smaller than the current digit.
Pattern: I12

One increasing relationship: 1 is less than 2.

Pattern: D21

One decreasing relationship: 2 is greater than 1.

Pattern: DD321

Both adjacent relationships must decrease.

Pattern: DI213

First decrease, then increase.

Important constraint: The pattern length can be at most 8 because we have only nine distinct digits (1–9) available.

2. Build the intuition

Look at a decreasing run such as DD. The three result positions must satisfy first digit > second digit > third digit. The source method handles this by assigning the next available digits while traversing that block from right to left.

💡
The key observation

When the outer loop reaches an I or the end, the inner loop walks backward and fills the current block. This is the central technique used by your implementation.

3. Java implementation from your DSA repository

This is the method from NumberFollowingAPattern.java. It uses a result array and a counter. The outer loop detects each I boundary (or the end), and the inner loop fills the current section from right to left.

static String printMinNumberForPattern(String s) {
    int n = s.length();                 // Number of relationships in the pattern.
    int count = 1;                      // Next smallest digit available (starts at 1).
    char[] ans = new char[n + 1];       // A pattern of length n needs n + 1 digits.

    // Visit every pattern position, including one virtual position after the end.
    for (int i = 0; i <= n; i++) {
        // An 'I' or the end marks the right boundary of the current block.
        if (i == n || s.charAt(i) == 'I') {

            // Fill this block from right to left so decreasing runs get larger
            // digits on the left and smaller digits on the right.
            for (int j = i - 1; j >= -1; j--) {
                ans[j + 1] = (char) ('0' + count); // Convert the next digit to a character.
                count++;                           // The next position gets the next digit.

                // Stop after filling the position immediately to the right of
                // a previous 'I'; that 'I' separates this block from the prior one.
                if (j >= 0 && s.charAt(j) == 'I') {
                    break;
                }
            }
        }
    }

    return new String(ans); // Convert the completed character array into the answer.
}

The source method assumes a non-null string containing only I and D. It does not validate the input or enforce the maximum pattern length; the problem's digit constraint (digits 1–9 without repetition) implies a maximum length of eight.

5. Why does the backward-fill strategy work?

The method assigns digits in increasing order of count, but fills positions within a block from right to left. For a decreasing section, this places smaller digits farther to the right and larger digits to the left, satisfying the required descending order when read from left to right.

When the inner loop reaches a preceding I, it stops because that boundary separates the current block from the previous one. The outer loop then continues to the next boundary. This produces the required order while using each digit once.

6. Complexity analysis

TIMEO(n)

The outer loop runs n + 1 times. Across the inner loops, each output position is assigned once.

AUXILIARY SPACEO(n)

The method allocates a character array of length n + 1 to build the result.

Here n is the length of the pattern. The input constraint n ≤ 8 ensures that the generated digits stay within 1 through 9.

7. Common mistakes and edge cases

  • Stopping before the end boundary. The outer loop must run through i == n so a final decreasing block is filled too.
  • Filling a decreasing block left to right. The inner loop moves backward so the resulting digits decrease when read from left to right.
  • Using a number type for the result. A string makes digit construction explicit and avoids treating the output as a numeric quantity.
  • Not validating the pattern. Only I and D are valid, and at most eight pattern characters are supported by the digit constraint.
