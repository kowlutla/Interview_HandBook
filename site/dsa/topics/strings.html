START WITH THE RIGHT QUESTION

How should I approach a string problem?

Do not start by writing loops. First identify what the problem asks you to preserve: character frequency, relative order, a one-to-one relationship, or a pattern between neighbouring positions.

  1. Understand the contractInput size, allowed characters, case sensitivity and expected output.
  2. Find the relationshipAre we counting, matching, mapping, comparing or constructing?
  3. Choose what to rememberA frequency array, map, last-seen index, two pointers or a stack.
  4. State the invariantExplain what must remain true after every iteration.
  5. Test the boundary casesRepeated characters, collisions, empty input and the smallest valid input.

01HASHING · BI-DIRECTIONAL MAPPING
EASY

Isomorphic Strings

Determine whether two strings have the same character structure, even when their actual characters are different.

INPUTs = "paper"t = "title"
OUTPUTtrue
UnderstandObservationSolutionWhy it worksPractice

1. Understand the problem

We are given two strings of equal length. We need to decide whether we can replace every character in the first string with a character in the second string so that the strings become identical.

The replacement must be consistent. If p becomes t once, every later p must also become t. The mapping must also be one-to-one: two different characters from the first string cannot share the same replacement character.

✓ Isomorphic"egg" → "add"

e → a and g → d. The repeated-character structure is preserved.

✕ Not isomorphic"foo" → "bar"

The two o characters would need to map to both a and r.

✕ Not isomorphic"ab" → "aa"

Both a and b would map to the same target a.

✓ Isomorphic"paper" → "title"

p → t, a → i, e → l, r → e.

What matters: The letters themselves do not matter. The positions at which characters repeat must have the same structure in both strings.

2. Build the intuition

Take s = "paper" and t = "title". Compare them position by position:

String spaper
String ttitle
Index01234

Notice the important relationship: the first p appears again at index 2. In the second string, t also appears again at index 2. The repeated positions match.

Now compare "foo" and "bar". The character o repeats at index 2, but the corresponding character r has not appeared before. Their histories do not match, so the strings cannot be isomorphic.

💡
The key observation

At every index, the current characters must have identical previous-occurrence histories. If one was seen before and the other was not—or their previous positions differ—the mapping is inconsistent.

3. Choose the data structure

There are two useful ways to maintain the one-to-one relationship.

Approach A · Explicit mapping
Use two maps

Maintain a forward map from s to t and a reverse map from t to s. For each pair of characters, verify that neither direction conflicts with a mapping already stored.

This is the most direct approach to explain because it mirrors the definition of a one-to-one mapping.

Approach B · Previous occurrence
Compare last-seen positions

Instead of storing the actual character mapping, store the last index at which each character appeared. At index i, the two last-seen values must be equal. Then update both values to i.

This avoids checking two maps separately. It works because a valid one-to-one mapping forces paired characters to repeat at exactly the same positions.

Recommended implementation below

4. Optimized Java solution

We use two integer arrays indexed by Java char. A value of -1 means that the character has not appeared yet. We compare the previous positions before updating either array.

public static boolean isIsomorphic(String s, String t) {
    if (s == null || t == null || s.length() != t.length()) {
        return false;
    }

    int charRange = Character.MAX_VALUE + 1;
    int[] lastSeenS = new int[charRange];
    int[] lastSeenT = new int[charRange];

    Arrays.fill(lastSeenS, -1);
    Arrays.fill(lastSeenT, -1);

    for (int i = 0; i < s.length(); i++) {
        char a = s.charAt(i);
        char b = t.charAt(i);

        if (lastSeenS[a] != lastSeenT[b]) {
            return false;
        }

        lastSeenS[a] = i;
        lastSeenT[b] = i;
    }

    return true;
}

Import required: java.util.Arrays. The method treats Java char values as the input alphabet (UTF-16 code units). For the common lowercase-English constraint, arrays of size 26 are sufficient. For arbitrary Unicode code points, iterate over code points and use integer-keyed maps.

5. Dry run: "paper" and "title"

Initially every character has last-seen index -1. We process both strings from left to right.

is[i]t[i]Previous positionsDecision
0pt-1 / -1Match → store 0
1ai-1 / -1Match → store 1
2pt0 / 0Match → store 2
3el-1 / -1Match → store 3
4re-1 / -1Match → store 4

Every pair has the same previous position. We finish the loop, so the result is true.

See where it fails: For s = "ab" and t = "aa", index 0 matches and stores position 0 for both a characters. At index 1, b has never appeared (-1), but a last appeared at 0. The mismatch immediately returns false.

6. Why is this correct?

Invariant: After processing every position before i, each character's stored value is exactly its most recent occurrence index in the part of the string already processed.

  • First occurrence on both sides: Both values are -1. The new pair can be mapped consistently, so we store i in both arrays.
  • Repeated occurrence on both sides: Their previous positions must be equal. If they differ, the repetition patterns differ and no consistent one-to-one mapping can exist.
  • Only one side repeats: One value is -1 and the other is not. This is also a conflict, caught by the same comparison.

If the scan completes, every pair has followed the same occurrence pattern. That is exactly the condition needed for a consistent one-to-one character mapping.

7. Complexity analysis

TIMEO(n + U)

One pass over n positions, plus initialization of two arrays of size U.

AUXILIARY SPACEO(U)

Two arrays, each covering the Java char range (U = 65,536).

Because the array size is fixed for this implementation, the scan itself is linear. If we use two hash maps instead, expected time is O(n) and auxiliary space is O(k), where k is the number of distinct characters encountered.

8. Common mistakes and edge cases

  • Using only a forward map. It accepts "ab" → "aa", even though two source characters collide on one target.
  • Comparing character frequencies only. Frequency counts ignore order. The positions of repeated characters are what matter.
  • Assuming every Java character fits in 256 slots. That is safe only under a stated byte/ASCII constraint, not for all Java char values.
  • Updating before comparing. Compare the previous occurrence information first; then record the current index.
  • Ignoring input assumptions. Clarify whether the problem guarantees equal lengths, lowercase English letters, ASCII or arbitrary characters.

Explain it in an interview: “I compare the previous occurrence index of the current character in both strings. A valid one-to-one mapping means the two characters must have appeared at the same previous position. If those positions differ, the mapping is inconsistent. This gives a single-pass solution.”

Remember: Isomorphic strings have the same repeat pattern. Compare the previous occurrence positions, not just the characters.

02GREEDY · STACK
MEDIUM

Minimum Number Following an I/D Pattern

Construct the smallest number whose adjacent digits follow the given increasing (I) and decreasing (D) pattern.

INPUTpattern = "IDID"
OUTPUT13254
UnderstandObservationSolutionWhy it worksPractice

1. Understand the problem

We are given a pattern made only of I and D. We must return the smallest number using distinct digits from 1 to 9, with one more digit than the pattern length.

  • I means the next digit must be greater than the current digit.
  • D means the next digit must be smaller than the current digit.
Pattern: I12

One increasing relationship: 1 is less than 2.

Pattern: D21

One decreasing relationship: 2 is greater than 1.

Pattern: DD321

Both adjacent relationships must decrease.

Pattern: DI213

First decrease, then increase.

Important constraint: The pattern length can be at most 8 because we have only nine distinct digits (1–9) available.

2. Build the intuition

Look at a consecutive run of D characters. For DD, the digits must decrease across three positions. The smallest possible arrangement is 321, not 123.

We can generate digits in increasing order and delay printing them until we know the decreasing run is complete. A stack is ideal: it reverses the order of the digits we have temporarily held.

💡
The key observation

Push the next smallest digit. When an I is reached, or when the pattern ends, pop all pending digits. This reverses each decreasing run while keeping the digits as small as possible.

3. Optimized Java solution

public static String smallestNumber(String pattern) {
    if (pattern == null || pattern.length() > 8) {
        throw new IllegalArgumentException("Invalid pattern length");
    }

    for (int i = 0; i < pattern.length(); i++) {
        char c = pattern.charAt(i);
        if (c != 'I' && c != 'D') {
            throw new IllegalArgumentException("Only I and D are allowed");
        }
    }

    Deque<Integer> stack = new ArrayDeque<>();
    StringBuilder result = new StringBuilder();

    for (int i = 0; i <= pattern.length(); i++) {
        stack.push(i + 1);

        if (i == pattern.length() || pattern.charAt(i) == 'I') {
            while (!stack.isEmpty()) {
                result.append(stack.pop());
            }
        }
    }

    return result.toString();
}

Imports required: java.util.ArrayDeque and java.util.Deque. The method returns a string because the result is a sequence of digits, not a quantity for arithmetic.

4. Dry run: "IDID"

We push digits in ascending order. At an I, we flush the stack. At the end, we flush whatever remains.

iPatternActionStack (top first)Output
0IPush 1, flush—1
1DPush 2, wait21
2IPush 3, flush—132
3DPush 4, wait4132
4ENDPush 5, flush—13254

Notice that the final flush is essential. Without it, the last decreasing run would remain in the stack and would never be added to the answer.

5. Why does the greedy choice work?

We assign the smallest unused digits in increasing order. A decreasing run requires those digits to appear in reverse order, and the stack performs exactly that reversal.

We flush as soon as an I is reached because that position ends the current decreasing run. This commits the smallest possible digits to the earliest positions without violating any relationship. The next run then receives the next smallest unused digits.

Every digit is pushed once and popped once. The algorithm therefore constructs a valid arrangement in linear time.

6. Complexity analysis

TIMEO(n)

Each of the n + 1 digits is pushed once and popped once.

AUXILIARY SPACEO(n)

The stack can hold up to n + 1 digits. The output needs O(n) space.

Here n is the length of the pattern. The input constraint n ≤ 8 ensures that the generated digits stay within 1 through 9.

7. Common mistakes and edge cases

  • Flushing on D. That breaks the decreasing run into pieces instead of reversing the complete run.
  • Forgetting the final flush. The pattern ending is also a boundary, even if the last character is D.
  • Using a number type for the result. A string makes digit construction explicit and avoids treating the output as a numeric quantity.
  • Not validating the pattern. Only I and D are valid, and at most eight pattern characters are supported by the digit constraint.
