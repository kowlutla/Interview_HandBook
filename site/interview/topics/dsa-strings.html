How to use this page

String questions are often array questions in disguise. A string gives you an ordered sequence of characters, and many problems ask you to maintain a relationship between positions, characters or previously seen values. The important first step is to decide what information must be remembered while scanning the input.

For each problem, focus on four things: the invariant (what must remain true while the loop runs), the data structure that maintains it, the reason the algorithm is correct, and the input constraints that affect the implementation. Java strings are immutable, so solutions that repeatedly concatenate inside a loop can accidentally become quadratic.

Mental model: four useful string patterns

Frequency / mapping

Track how often a character appears or which character it maps to. Use arrays when the character set is bounded; use maps when it is not.

Last-seen position

Remember the most recent index for each character. This often replaces a more complicated pair of maps.

Two pointers

Compare or process characters from different ends or advance through two strings together.

Greedy construction

Build the answer while preserving a local rule, then prove that the choice also gives the required global result.

Problems

1. Isomorphic Strings Mapping · Easy

Problem statement

Given two strings s and t, determine whether they are isomorphic. Two strings are isomorphic when every character in the first string can be consistently replaced by exactly one character in the second string, while preserving the order of characters. Two different characters cannot map to the same character.

Examples

s = "egg", t = "add"       → true
s = "foo", t = "bar"       → false
s = "paper", t = "title"   → true
s = "ab", t = "aa"         → false

Pattern and intuition

The key requirement is a one-to-one mapping. Checking only the mapping from s to t is not enough: both a and b could map to x, even though the mapping must be reversible. We therefore need to check the relationship in both directions.

A clean way to do that is to remember the last index at which each character appeared. At every position, the two current characters must have the same previous-seen position. If one character is appearing for the first time while the other has appeared before, their histories differ and the strings cannot be isomorphic.

Optimized Java solution

public static boolean isIsomorphic(String s, String t) {
    if (s.length() != t.length()) {
        return false;
    }

    int[] lastSeenS = new int[Character.MAX_VALUE + 1];
    int[] lastSeenT = new int[Character.MAX_VALUE + 1];

    for (int i = 0; i < s.length(); i++) {
        char a = s.charAt(i);
        char b = t.charAt(i);

        if (lastSeenS[a] != lastSeenT[b]) {
            return false;
        }

        // Store i + 1 so that zero means "never seen".
        lastSeenS[a] = i + 1;
        lastSeenT[b] = i + 1;
    }

    return true;
}

This implementation works with Java char values (UTF-16 code units), rather than assuming that every input character fits in an ASCII-sized array. If a problem defines characters as Unicode code points rather than Java char values, convert the strings to code-point arrays and use a map keyed by integer code points.

Every pair has matching previous-seen positions, so the strings are isomorphic. For "ab" and "aa", the second position compares an unseen b (zero) with an already-seen a (one), so the method returns false.

Complexity analysis

MetricComplexityReason
TimeO(n + U)One pass over n characters; the two fixed arrays have U = 65,536 entries to initialize to zero.
Auxiliary spaceO(U)Two arrays indexed by the Java char range.

If the input contract is restricted to ASCII, arrays of size 128 or 256 reduce the fixed space. If the character set is unrestricted or sparse, two hash maps provide expected O(n) time and O(k) space, where k is the number of distinct characters.

Common mistakes

  • Checking only one mapping direction. This misses two source characters mapping to the same target character.
  • Using an array of length 256 without stating an ASCII/byte-character constraint. A Java char can have a value well above 255.
  • Comparing only character frequencies. Equal frequencies do not guarantee that the order-based mapping is consistent.

Remember: Isomorphism is a bijection. At each index, both strings must have the same previous-occurrence history.

2. Minimum Number Following an I/D Pattern Greedy · Medium

Problem statement

Given a pattern containing only I (increasing) and D (decreasing), construct the smallest number that follows the pattern. Use each digit from 1 to 9 at most once. The answer has one more digit than the pattern, so the pattern can contain at most eight characters.

Examples

pattern = "IDID"  → "13254"
pattern = "D"     → "21"
pattern = "II"    → "123"
pattern = "DDI"   → "3214"

For IDID, the digits must satisfy first digit less than second, second greater than third, third less than fourth, and fourth greater than fifth. Among all valid permutations, 13254 is the smallest.

Pattern and intuition

A run of consecutive D characters forces a descending block. To make that block as small as possible, use the smallest available digits, but place them in reverse order. Increasing positions can then be filled in the smallest order that does not break those constraints.

A simple implementation uses a stack. Push the next smallest digit for each position. Whenever we see an I, or reach the end, pop the stack into the answer. Popping reverses each pending run, which is exactly what a decreasing run needs.

Optimized Java solution

public static String smallestNumber(String pattern) {
    if (pattern == null || pattern.length() > 8) {
        throw new IllegalArgumentException(
            "Pattern must contain at most 8 characters");
    }

    for (int i = 0; i < pattern.length(); i++) {
        char c = pattern.charAt(i);
        if (c != 'I' && c != 'D') {
            throw new IllegalArgumentException(
                "Pattern may contain only I and D");
        }
    }

    StringBuilder answer = new StringBuilder();
    Deque<Integer> stack = new ArrayDeque<>();

    for (int i = 0; i <= pattern.length(); i++) {
        stack.push(i + 1);

        if (i == pattern.length() || pattern.charAt(i) == 'I') {
            while (!stack.isEmpty()) {
                answer.append(stack.pop());
            }
        }
    }

    return answer.toString();
}

Imports: java.util.ArrayDeque and java.util.Deque. The algorithm pushes digits in increasing order. It flushes the stack at an increasing boundary, so each decreasing run is emitted in reverse order. Validation makes the input assumptions explicit rather than silently producing an invalid result.

Why the greedy choice is correct

Digits are pushed in ascending order, so the algorithm never delays a smaller digit in favour of a larger one. A pending decreasing run must appear in reverse order; the stack produces exactly that reversal. Flushing at every I ends the decreasing run at the earliest position where the pattern permits it. Therefore each completed block uses the smallest available digits in the only order that satisfies its local constraints, giving the lexicographically smallest valid number overall.

Complexity analysis

MetricComplexityReason
TimeO(n)Each digit is pushed once and popped once.
Auxiliary spaceO(n)The stack holds at most n + 1 digits; the output is O(n).

Here n is the pattern length. Because the problem limits n to eight, the digit constraint is also satisfied: the output uses exactly the digits 1 through n + 1.

Common mistakes

  • Flushing the stack on D. A decreasing run needs to be reversed as a whole.
  • Forgetting to flush after the final pattern character. The final decreasing run has no following I to trigger it.
  • Using digits beyond 9. With distinct digits from 1 to 9, the pattern length cannot exceed eight.

Remember: Push the next smallest digit; pop at every I and at the end. The stack reverses each decreasing run.
