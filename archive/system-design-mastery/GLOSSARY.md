# Glossary

- **Admission control:** deciding whether to accept work based on capacity or policy.
- **Anti-corruption layer:** an adapter boundary that translates an external or legacy model into local domain concepts without leaking the upstream model into the core.
- **API gateway:** API-facing entry point that routes requests and may enforce shared authentication integration, quotas, validation, transformation and telemetry; it does not replace domain-level authorization.
- **Backpressure:** mechanism that slows upstream production when downstream capacity is insufficient.
- **CDN (Content Delivery Network):** geographically distributed edge infrastructure that can cache and deliver eligible content closer to users.
- **Circuit breaker:** temporarily stops calls to a failing dependency to limit wasted work and cascading failure.
- **Connection draining:** stops assigning new work to a target while allowing eligible in-flight work to complete within a bounded period.
- **Control plane:** components that configure, coordinate or observe a system's behavior rather than directly handling its main application traffic.
- **Data plane:** components that process the system's primary traffic or data operations under the active configuration.
- **Feature flag:** runtime-controlled switch that changes feature exposure independently of deploying code; it needs safe defaults, ownership, testing and removal discipline.
- **Fencing token:** ordered token used to reject stale actors after ownership changes.
- **Load balancer:** component that selects eligible targets for connections or requests according to routing, health, capacity and policy.
- **Microservices:** independently deployable services organized around capabilities and explicit contracts; they add network, data consistency and operational costs.
- **Origin shield:** intermediate cache layer used by a CDN to reduce repeated cache-miss traffic reaching the origin.
- **Reverse proxy:** server-side proxy that receives requests on behalf of backend/origin services and forwards them.
- **Service mesh:** infrastructure for service-to-service traffic policy, workload identity and telemetry, commonly implemented with proxies and a control plane.
- **Write amplification:** physical storage writes relative to logical application writes; important for storage-engine capacity and latency.
- **Write skew:** concurrent transactions read overlapping state and update different rows, jointly violating an invariant even though each local update succeeds.
- **Availability:** proportion of time or requests meeting a defined success criterion.
- **Bandwidth:** transfer rate; distinguish bit/s from byte/s.
- **Batch processing:** processing a bounded collection of input data as a job or stage, usually with results available after that work completes.
- **CI/CD:** continuous integration and continuous delivery/deployment; automated build, test, validation and release-promotion processes whose exact production-approval model should be explicit.
- **IAM (Identity and Access Management):** policies and lifecycle processes for human/workload identities, authenticators, entitlements, revocation and audit.
- **Micro-batch processing:** stream-like processing that groups incoming records into small bounded batches on a recurring schedule.
- **Stream processing:** continuous processing of event records, often with state, event-time windows, checkpoints and late-event handling.
- **Synthetic check:** an automated probe that executes a controlled user journey from a known vantage point to test a defined service path.
- **Bulkhead:** isolation limiting the impact one failure or workload can have on another.
- **Cache hit ratio:** fraction of lookups served by cache; define denominator and measurement window.
- **Causal consistency:** causally related operations are observed in an order consistent with that causality.
- **CAP theorem:** under its formal model, during a network partition a distributed read/write object cannot guarantee both linearizability and availability for every request.
- **Concurrency:** tasks are in progress over overlapping periods; they need not execute simultaneously.
- **Consistency model:** rules defining which values and operation orders clients may observe.
- **Consensus:** processes agree on a value or ordered decisions despite a specified class of failures.
- **Database-per-service:** each service owns its authoritative data boundary; it need not imply a separate physical database server for every service.
- **Durability:** acknowledged committed changes survive the failures covered by the system's contract.
- **Eventual consistency:** if updates stop and communication/reconciliation continues under the model's assumptions, replicas eventually converge; interim reads are not fully specified by this phrase alone.
- **Idempotency:** repeating an operation has the same intended effect within a defined scope and key lifetime.
- **Idempotent receiver:** a message/command handler that detects or safely absorbs duplicate deliveries, typically using a stable operation ID and an atomic local effect.
- **Inbox pattern:** a consumer records a stable message or operation identifier in the same transaction as its local business effect, so duplicate deliveries can be detected safely.
- **Last-write-wins (LWW):** conflict-resolution rule that keeps the update judged newest by a chosen ordering rule; clock ties/skew and discarded concurrent intent make its semantics important.
- **Latency:** elapsed time between defined start and end events.
- **Linearizability:** each operation appears to take effect atomically between invocation and response, respecting real-time order.
- **Little's Law:** for a stable system, average work in the system L equals arrival rate λ times average time W: L = λW.
- **Load shedding:** intentionally rejecting lower-priority work to preserve critical service.
- **Point-in-time recovery (PITR):** restoring a data system to a chosen point in time using a base backup and the required transaction logs or change history, subject to retention and recovery guarantees.
- **Partitioning:** dividing a dataset or workload into subsets.
- **QUIC:** secure, UDP-based transport protocol providing streams, connection migration and transport features used by HTTP/3; it does not eliminate loss, congestion or capacity limits.
- **Quorum:** set of participants sufficient under a protocol's rules; quorum size alone does not guarantee a consistency level.
- **RPO:** Recovery Point Objective; acceptable data-loss window expressed in time.
- **RTO:** Recovery Time Objective; target time to restore service after disruption.
- **Safety:** nothing forbidden happens, such as two conflicting values both being committed as the unique decision.
- **SLO:** Service Level Objective; target for a measured service-level indicator over a defined window.
- **Tail latency:** high-end latency distribution, often described using p95 or p99.
- **Throughput:** amount of useful work completed per unit time.
- **Utilization:** fraction of a resource's capacity that is busy; high utilization can sharply increase queueing delay.
- **Vector clock:** logical-clock structure tracking causal relationships and helping identify concurrent events.
- **Watermark (stream processing):** estimate or policy boundary indicating how far event time is believed to have progressed; it influences when a window may be considered complete while late events may still require handling.

- **Client-side prediction:** client-side simulation of a likely result before authoritative server confirmation, later reconciled with authoritative state.
- **Conflict-free Replicated Data Type (CRDT):** a data type with defined merge/update properties that permit replicas to converge under stated assumptions; convergence alone does not preserve arbitrary business invariants.
- **Hydration:** attaching client-side behavior to server-rendered HTML, requiring compatible initial state and rendering assumptions.
- **Local-first software:** design approach that treats the user's local copy and ability to work with it as primary, with synchronization to other replicas as a coordinated concern.
- **Offline-first:** design approach that preserves useful application behavior during disconnection through local state and an explicit synchronization/reconciliation protocol; it does not imply that every operation can be finalized offline.
- **Micro-frontend:** independently owned or delivered UI module integrated into a larger application, adding runtime, interface, security and performance concerns.
- **Optimistic UI:** presenting a proposed state change before the authoritative service confirms it; pending, rejected and unknown outcomes still need explicit handling.
- **Operational Transformation (OT):** method for transforming concurrent editing operations so they can be applied consistently under a defined collaboration protocol.
- **Server-Sent Events (SSE):** HTTP-based one-way server-to-client event stream; durable replay requires an application-level cursor/history contract.
- **SFU (Selective Forwarding Unit):** media server that forwards selected participant streams to others rather than mixing all media into one output.
- **STUN:** protocol used by a peer to discover network address information for connectivity establishment; it does not guarantee a direct path will work.
- **Tombstone:** retained deletion marker used to propagate a deletion to replicas and prevent stale copies from being silently resurrected.
- **TURN:** relay protocol/service used when peers cannot establish a suitable direct network path; relaying adds bandwidth and operational cost.
- **WebRTC:** browser/device APIs and protocols for real-time peer connections carrying media or data, commonly requiring signaling and sometimes STUN/TURN infrastructure.
